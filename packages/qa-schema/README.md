# @qa/schema

The versioned wire contracts every component agrees on. This package is the
single source of truth for every payload that crosses a component boundary.
Nothing else in this repo may re-declare one of these shapes.

| Schema                | Contract | Between                                     |
| --------------------- | -------- | ------------------------------------------- |
| `test-case@1`         | A        | Test Planner → Executor                     |
| `application-map@1`   | B        | Discovery → Planner → Backend               |
| `test-plan@1`         | —        | Planner agent `out.json` → Backend          |
| `execution-result@1`  | —        | Executor → Backend → Failure Analyst        |
| `finding@1`           | F        | Failure Analyst → Report                    |
| `daemon-envelope@1`   | D        | Backend ↔ Daemon control plane              |

## Layout

```
schemas/       the JSON Schema documents (draft 2020-12) — the source of truth
fixtures/      valid/ and invalid/ documents per contract, plus expectations.json
src/           the TypeScript binding: validator, registry, CLI
src/*.generated.ts   generated by `make gen`, never hand-edited
scripts/       the generator and the expectations builder
bin/           the `qa-schema` command
```

The Go binding lives in `server/pkg/qaschema`, and `make gen` mirrors it byte
for byte into `daemon/pkg/qaschema`. Edit the copy under `server/`; the daemon
copy carries a header saying so. The package may only import the standard
library — the generator refuses to mirror a file that names its own module path.

## Using it

TypeScript:

```ts
import { validate, type TestCase } from '@qa/schema';

const result = validate('test-case@1', payload);
if (!result.valid) {
  // every entry carries the JSON Pointer of the field that failed
  throw new Error(result.errors.map((e) => `${e.instancePath}: ${e.message}`).join('; '));
}
const testCase = payload as TestCase;
```

Go:

```go
if err := qaschema.MustBeValid("daemon-envelope@1", frame); err != nil {
    return fmt.Errorf("reject frame: %w", err)
}
```

Decode with `qaschema.DecodeJSON` rather than `encoding/json` directly if you
are going to call `Validate` on an already-decoded value: `integer` cannot be
told from `number` once every value has become a `float64`.

Command line (CI, shell plumbing):

```
make gen                                        # builds dist/, which the bin needs
pnpm exec qa-schema list
pnpm exec qa-schema validate test-case@1 plan.json
pnpm exec qa-schema validate --json finding@1 out.json
```

Exit codes: `0` valid, `1` invalid, `2` the command itself was wrong (bad usage,
unreadable file, unknown schema id). CI can tell "this document is bad" from
"this pipeline is bad".

## Rules

- **Schemas are the source.** Go and TypeScript types are generated by
  `make gen` and never hand-edited. `SCHEMA_IDS` is generated from the files on
  disk, so it cannot drift from what is actually there.
- **The `action` and `assertion.type` vocabularies are frozen at v1.** Adding a
  member is a new minor version, and a consumer that meets a member it does not
  recognise must fail loudly. Never skip it. See [VERSIONING.md](./VERSIONING.md).
- **Everything from outside is validated before anything else touches it.** A
  page under test can put arbitrary text into a label and an AI CLI can write
  arbitrary JSON into `out.json`; a schema is what stops either from being
  treated as structure.
- **Every object is closed** (`additionalProperties: false`). An unexpected
  field is a contract mismatch, not something to ignore.

## Why the validator is hand-written

The Go backend and this package have to return the *same verdict* and the *same
error paths* for the same document. Two different third-party validators agree
on validity but not on error output, and — worse — both silently ignore keywords
they do not implement, so a tightened schema can quietly become a weaker one.

This validator implements a documented subset of draft 2020-12 and **refuses to
load a schema that uses a keyword outside that subset**, in both languages. It
also rejects regex patterns that only work in one of the two engines (lookaround
and backreferences, which JavaScript accepts and Go's RE2 does not).

`fixtures/expectations.json` records the exact error list for every fixture. The
TypeScript suite asserts its output against it, and so does the Go suite — that
file is what makes "the two validators agree" a test rather than an intention.

Supported keywords: `type` `enum` `const` `$ref` `$defs` `properties`
`patternProperties` `additionalProperties` `propertyNames` `required`
`dependentRequired` `minProperties` `maxProperties` `items` `minItems`
`maxItems` `uniqueItems` `minLength` `maxLength` `pattern` `format` `minimum`
`maximum` `exclusiveMinimum` `exclusiveMaximum` `multipleOf` `allOf` `anyOf`
`oneOf` `not` `if` `then` `else`, plus the standard annotations and any `x-`
extension. `format` is an assertion here, not an annotation, and is limited to
`uuid`, `date-time`, `uri` and `regex`.

## Working on the contracts

```
make gen                                        # regenerate types, mirrors, dist
pnpm --filter @qa/schema run test               # TypeScript suite
cd server && go test ./pkg/qaschema/            # Go suite
pnpm --filter @qa/schema run gen:expectations   # only when a change to the
                                                # error output is intended
```

`make gen` must be idempotent: running it twice leaves the working tree clean.
`gen:expectations` is deliberately not part of it — regenerating the oracle on
every build would turn a behaviour regression into a silent diff.
